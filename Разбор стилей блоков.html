Часть 1

Где шаблон ломается и что я сделал

Слева код из шаблонов Content_SEO, справа мой вариант. Это не «мне так больше нравится»: каждый случай можно проверить на живой странице.

Плашки работают только если их 4, 5 или 6

Плашка с текстомТекст с иконкой
Было 
.pad {
  grid-template-columns: repeat(6, 1fr);
}
.pad--4 .pad__block { grid-column: span 3 }
.pad--5 …
.pad--6 .pad__block { grid-column: span 2 }

Ширина прописана только для 4, 5 и 6 плашек, в инструкции к шаблону так и написано. Если в тексте 3 преимущества или 8 пунктов, каждая плашка занимает 1/6 строки, и половина ряда пустая. С иконками то же самое, там .point--4/5/6.

Стало 
.grid-auto { grid-template-columns: repeat(12, 1fr) }
.grid-auto--3 > * { grid-column: span 4 }
.grid-auto--7 > *:nth-child(-n+4) { span 3 }
…  от 1 до 10 плашек

Я сделал одну сетку на все виды плашек. Ставишь класс с нужным числом, и от 1 до 10 плашек раскладываются ровными рядами. Новый вид плашек тоже её использует, ничего не надо дублировать.

Проще говоря: если в текстовке три преимущества, сетку больше не надо переписывать руками.

У плашки жёсткая высота

Плашка с текстом
Было 
.pad { grid-auto-rows: 88px }

Каждый ряд ровно 88px. Если текст в плашке длиннее двух-трёх строк, он вылезает за неё и наезжает на ряд ниже.

Стало 
.pad { grid-auto-rows: minmax(88px, auto) }

Минимальная высота та же, но плашка растёт вместе с текстом. Одна строчка, а проблема уходит.

На планшете плашки сразу в одну колонку

Текст с иконкой
Было 
@media (max-width: 1024px) {
  .point { grid-template-columns: 100% }
}

Из шести колонок сразу в одну. На планшете получается длинная лента плашек во весь экран.

Стало 
@media (max-width: 1024px) {
  .grid-auto { repeat(2, 1fr) }
  /* нечётная последняя — на всю ширину */
}
@media (max-width: 768px) { 1fr }

Я добавил промежуточный шаг: на планшете две колонки, на телефоне одна. Если плашек нечётное число, последняя растягивается на всю ширину, чтобы не висела одна.

Картинка вшита прямо в стили

Текст на большой картинке
Было 
.big-card {
  background-image:
    url(//b2ccdn…/stambul/bg.webp);
}

Фон прописан в CSS. Чтобы поставить другую картинку, приходится лезть в стили. А два таких блока с разными фонами на одну страницу вообще не поставить.

Стало 
.big-card { background-image: var(--bg) }

<div class="big-card"
  style="--bg: url(…); --bg-m: url(…)">

Стили у всех блоков одинаковые, а адрес картинки указан в самом блоке. Таких блоков на странице может быть сколько угодно, и у каждого свой фон.

Скрипт слайдера написан под один слайдер

Слайдер
Было 
new Swiper(".js-slider-stambul", {
  loop: true,
  pagination: { el: ".js-pagination-stambul" }
});

Классы конкретного слайдера вписаны прямо в скрипт. Чтобы добавить второй слайдер, надо копировать скрипт и придумывать новые классы. В инструкции к шаблону даже отдельно предупреждают, что при переименовании их надо поменять и в скрипте, иначе слайдер не заработает. Плюс зацикливание включено всегда, даже если слайдов меньше, чем влезает на экран.

Стало 
document.querySelectorAll(".slider-block")
  .forEach(block => {
    perView = block.dataset.perView;
    loop: slidesCount >= perView * 2,
    on lock → .slider-block--locked
  });

Один скрипт находит все слайдеры на странице сам. Сколько слайдов показывать, пишется в разметке (data-per-view). Зацикливание включается, только когда слайдов хватает. Если все слайды и так видны, стрелки и точки прячутся.

Проще говоря: слайдер вставляется как есть, переименовывать ничего не нужно, а значит и ошибиться негде.

Таблица
Было 
.turkey-hotels-container { width: 1370px }
.turkey-hotels-th { background: #E6F4FF;
  color: #2c3e50 }
.turkey-hotels-table-container {
  border-radius: 8px }
.turkey-hotels-search { … }   /* нет в разметке */
.turkey-hotels-btn { … }      /* нет в разметке */
  • Из 22 правил CSS 10 описывают поиск, масштаб, кнопки и подсветку. Самих этих элементов в разметке нет, скрипта тоже нет, а стили всё равно едут на каждую страницу.
  • Цвета свои (#2c3e50, #ddd), не фирменные. Скругление 8px, а у всех остальных блоков 20px. Ширина 1370px задана отдельно, мимо общей сетки. Заголовок оформлен не так, как другие заголовки на странице.
  • Классы turkey-hotels-* и id="turkeyHotelsTable" привязаны к одной странице. Если поставить две таблицы, у них будет одинаковый id.
Стало 
.airline-table thead { background: #0092d0 }
.airline-table tbody tr:nth-child(even) {
  background: #f5f5f8 }
.airline-table { border-radius: 20px }
.airline-table__wrap { overflow-x: auto }

9 правил, и все используются. Фирменный синий в шапке, серые полоски через строку, скругление как у остальных блоков, общая ширина страницы. На телефоне таблица листается вбок, а не сжимает колонки. Таблица в части 2 ниже сделана как раз в этом оформлении.

Часть 2

Почему страницы выглядят по-разному

Мои блоки опираются на пару дополнений к общим стилям: сетку .grid-auto и отступы между секциями (.wrapper 12px плюс класс .mt-1). Сами общие стили я взял из актуального шаблона один в один, а свои дополнения вынес отдельным блоком в конец файла, чтобы их было сразу видно.

Отступы между секциями в обеих системах в итоге одинаковые: 80px на компьютере и 60px на телефоне. Проблема появляется, когда блоки одной системы ставят на страницу с общими стилями другой:

Что вставилиНа какую страницуЧто получится
Мои плашки и карточкиТолько с общими стилями из Content_SEOСетки нет, плашки встают друг под другом
Блоки из Content_SEO без класса .mt-1С моими общими стилямиМежду секциями 24px вместо 80px
Мои блокиС моими общими стилямиВсё как задумано
Блоки из Content_SEOС общими стилями из шаблонаВсё как задумано, кроме случаев из части 1

Дело не в том, что чей-то код хуже. Мы просто сейчас пользуемся двумя разными наборами, и на стыке они конфликтуют.

Часть 3

Что я предлагаю

Я не предлагаю выкинуть наши шаблоны и взять мои целиком. Предлагаю перенести в общие шаблоны конкретные исправления из части 1, а дальше всем работать с одним набором:

  1. Сетку плашек .grid-auto в общие стили вместо .pad--4/5/6 и .point--4/5/6.
  2. minmax(88px, auto) вместо жёсткой высоты плашки.
  3. Фон через var(--bg) в «Тексте на большой картинке».
  4. Общий скрипт слайдера, который находит все .slider-block на странице.
  5. Таблицу в фирменном оформлении вместо turkey-hotels-*.
  6. Разметку вопросов-ответов в раскрывашке.
  7. Один набор шаблонов на всех. Тогда страницы будут выглядеть одинаково, кто бы их ни собирал. Если решим, что какие-то из пунктов не нужны, я спокойно уберу их у себя, лишь бы набор был общий.

Могу показать любой пункт на живой странице или в справочнике, там все блоки открываются с кодом.
